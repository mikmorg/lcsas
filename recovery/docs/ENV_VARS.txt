LCSAS RECOVERY -- ENVIRONMENT VARIABLE REFERENCE
=================================================

DEFAULT-CHOICE PRINCIPLE
─────────────────────────
Features that only add cost or disk use are opt-in (default OFF).
Features that change observable behavior — i.e., the restore would
behave differently without them — are also opt-in unless the feature
is always safe and the penalty of forgetting it is data loss or silent
failure, in which case it is opt-out (default ON).

This principle exists so you can predict restore behavior without
reading source code.  Each "Why this default" entry below maps to one
of the two clauses above.

WHICH PROGRAM READS EACH VARIABLE
──────────────────────────────────
Each entry has a "Read by:" line.  The programs are:

  restore.sh     the restore script for Linux and macOS
  restore.bat    the restore script for Windows
  tier 1         lcsas-restore (lcsas-restore.exe on Windows), the
                 program both scripts start to do the restore
  tier 3         standalone_restorer.py, the Python reader that only
                 restore.sh starts
  lcsas-keyshare the share card combiner both scripts start

A variable that tier 1 or lcsas-keyshare reads works with both
scripts: they pass their environment on.  A "Windows:" paragraph says
what restore.bat does when it differs from restore.sh.

CREDENTIALS
───────────

LCSAS_PASSWORD
  Default:  unset (prompts on stdin)
  Since:    Phase 1
  Read by:  restore.sh and restore.bat
  What:     Password for the Rustic repository.  When set,
            restore.sh writes it to a temp file (mode 600) instead of
            reading interactively.  When LCSAS_PWFILE (or --key) is
            set too, the file wins and this is not used.
            A wrong one is not asked for again: the run stops with
            exit 77.  (Typed at the prompt, a wrong password is caught
            before the restore starts and asked for again; since rc6,
            #608.)  restore.sh uses it for the first backup set only:
            the "Restore another backup set?" run asks again.
  Windows:  restore.bat honours it too (since rc6, #608), after
            LCSAS_PWFILE.  It writes it to a temp file in %TEMP%,
            deleted on every way out, and tries it with
            lcsas-restore --list-snapshots before the restore: a wrong
            one is said plainly, and the password is then asked on the
            keyboard.  It is used for every backup set restored in the
            run.
  Why:      Opt-in — credentials must never appear in the environment
            by default.  Scripted / CI use requires explicit action.

LCSAS_PWFILE
  Default:  unset (prompts on stdin)
  Since:    Phase 1
  Read by:  restore.sh (also as --key FILE) and restore.bat
  What:     Path to a file that holds the password.  Tier 1 drops the
            line breaks at the end of the file; everything before them
            is the password, exactly.  Preferred over LCSAS_PASSWORD
            in scripts because the secret stays in a file rather than
            a shell variable.  restore.sh hands the file itself to the
            restore.  A wrong password stops the run with exit 77, as
            for LCSAS_PASSWORD, and restore.sh asks again for the
            next backup set.
  Windows:  restore.bat honours it too (since rc6, #608), before
            LCSAS_PASSWORD: it copies the file's exact bytes (copy /b)
            to its own temp file in %TEMP% and never deletes yours.
            A read-only file (on a CD, a locked USB stick) is fine:
            the copy loses the read-only mark, and is deleted on
            every way out (a later run deletes one left by a closed
            window).  A line break at the end is ignored.
            RECOVER_WINDOWS.txt, "THE PASSWORD", shows how to write
            such a file from a hidden PowerShell prompt (Windows
            PowerShell 5.1 is enough).  A file that cannot be read, or
            a wrong password, falls back to the keyboard.  It is used
            for every backup set restored in the run.
  Why:      Opt-in — same reasoning as LCSAS_PASSWORD.

LCSAS_PW
  Default:  unset (prompts on stdin)
  Since:    restore.bat only, before rc6
  Read by:  restore.bat only
  What:     The older restore.bat name for LCSAS_PASSWORD, kept: used
            when neither LCSAS_PWFILE nor LCSAS_PASSWORD is set.
            restore.sh does not read it.
  Why:      Opt-in — same reasoning as LCSAS_PASSWORD.

LCSAS_SHARES_DIR
  Default:  unset (asks for the share cards when the set's password
            is split, else for the password)
  Since:    rc6 (#607)
  Read by:  restore.sh and restore.bat (both hand the files to
            lcsas-keyshare)
  What:     A folder of share card files, one card per file (the
            printed card's text, or just its words).  restore.sh
            rebuilds the password from every file in it with the
            bundled lcsas-keyshare (more than K cards is fine) and asks
            nothing.  A file with a mistake is named and left out, and
            the rest are combined.  If they cannot rebuild it, the run
            stops with exit 77.  LCSAS_PWFILE and LCSAS_PASSWORD come
            first.  restore.sh uses it for the first backup set only.
            Unset, restore.sh asks for exactly K cards, one per line,
            when the set's marker (metadata/<id>/LCSAS_REPO.txt) says
            split=K-of-N; P at that prompt types the password instead.
  Windows:  restore.bat combines the files in a new folder under
            %TEMP% that it then deletes.  It uses the folder when
            LCSAS_PWFILE, LCSAS_PASSWORD and LCSAS_PW are not set, for
            any backup set, split or not in its marker.  Every file
            must be a card typed right: one mistyped word in any file
            makes lcsas-keyshare refuse the whole folder (exit 3,
            naming the word), even when K good cards remain.  If the
            cards do not rebuild the password, it says why and asks on
            the keyboard (the cards, or P and the password).
  Why:      Opt-in — the cards are secrets; scripted use needs an
            explicit choice, like LCSAS_PWFILE.  The folder also serves
            a set whose marker does not say its password is split.

DISCOVERY OVERRIDES
───────────────────

LCSAS_REPO
  Default:  unset (prompts when multiple repositories found)
  Since:    Phase 14
  Read by:  restore.sh (also as --repo NAME) and restore.bat
  What:     Backup set to restore, by its id (the name of its
            metadata/<id>/ folder on the discs) or, since rc6 (#606),
            by its name (name= in that folder's LCSAS_REPO.txt) or its
            plain-letters name (name_cmd=, as restore.bat shows it).
            Skips the numbered list on archives with several sets.  A
            name two sets share matches neither: use the id.  The list
            itself shows each set's name (its id when it has no marker).
  Windows:  restore.bat (since rc6, #606) matches the id, then the
            name or name_cmd, case-blind, and takes the first set that
            matches: with two sets of the same name, use the id.  A
            name with letters outside A-Z may not match in cmd's code
            page; use the id or the name the menu shows.
  Why:      Opt-in — omitting it is correct and safe; it just shows an
            interactive prompt.  Setting it changes which repository's
            data is restored; wrong value exits with an error.

LCSAS_TARGET
  Default:  unset (auto-detected from uname -m and uname -s)
  Since:    Phase 21
  Read by:  restore.sh and restore.bat
  What:     Override the rust-triple used to select which lcsas-restore
            and rustic-static binaries to run (e.g.,
            x86_64-unknown-linux-musl).  Useful when uname -m
            misreports on an emulated or cross-compiled host.
            Relocated, restore.sh copies only that triple's folder.
  Windows:  restore.bat reads it too: unset, it picks
            x86_64-pc-windows-gnu from PROCESSOR_ARCHITECTURE (AMD64
            or x86), and refuses ARM64.  It copies only that triple's
            programs into the tools folder.
  Why:      Opt-in — auto-detection is correct in the vast majority of
            cases; overriding it is an escape hatch for unusual hosts.

LCSAS_META_DISC
  Default:  unset (auto-detected via mtab / findmnt)
  Since:    Phase 20
  Read by:  restore.sh and tier 1 (tier 1 reads it only when its
            own --meta-disc option is not given)
  What:     Mount point of the meta disc.  Tells restore.sh
            and the tier-1 binary to exclude that path from pack
            searches so an heir with a single optical drive can eject
            the meta disc and reuse the drive for data discs.  Both
            skip it only while the META disc is still in it: once a
            data disc is in that drive, it is searched.  restore.sh
            finds the mount point itself only when it relocates off
            the disc.  Set, it also turns on the newest-data-disc step
            (LCSAS_NEWEST_DISC_PROMPT) for a copy of the META disc run
            where it is.
  Windows:  restore.bat does not read it.  It passes the META disc's
            drive letter to tier 1 as --meta-disc itself.
  Why:      Opt-in — auto-detection (mtab probe) handles the common
            case correctly; explicit set is for unusual mount layouts
            or initramfs environments where mtab is absent.

LCSAS_MOUNT_DIRS
  Default:  unset → /Volumes:/media/<user>:/media:/mnt:
            /run/media/<user>:/run/media
  Since:    Phase 20
  Read by:  restore.sh and tier 1
  What:     Colon-separated list of directories scanned for mounted
            data discs.  Overrides the compiled-in default list on
            both the shell side (restore.sh) and the C side
            (lcsas-restore), which share the same value via export.
            Set to '' (empty string) to disable auto-scan entirely.
            On Windows, lcsas-restore splits it on ';' (':' is in
            every drive letter) and has no default list: it searches
            the root of every optical drive (D:\ and so on) instead,
            each time it looks for a disc.  restore.bat does not read
            it: it passes its drive letters to tier 1 as
            --mount-parent, and tier 1 reads the variable only when
            no --mount-parent is given.
  Why:      Opt-in — the compiled-in default covers Linux, macOS, and
            BSD conventions.  Override only when discs are mounted
            under a non-standard path (e.g., systemd-managed
            /run/media/$USER/ not in the default list) or in test
            environments that need a controlled directory.

BEHAVIOR KNOBS
──────────────

LCSAS_PACK_CACHE_DIR
  Default:  auto  (opt-out / default ON)
  Since:    Phase 24
  Read by:  restore.sh, restore.bat and tier 1 (tier 1 does the
            copying; the scripts choose the folder)
  What:     Opportunistic pack cache directory.  Three values:
              auto    (default when unset) → pack-cache/ in the tools
                      folder (see LCSAS_TOOLS_DIR), so a stopped
                      restore carries on with the discs it already
                      read.  Without a tools folder (no $HOME), a
                      temporary folder under ${TMPDIR:-/tmp} that is
                      removed when the run ends.  (Before rc6 it was
                      ${TMPDIR:-/tmp}/lcsas-pack-cache.<pid>, which no
                      run removed, #616.)
              <path>  → use that exact path (persists across runs).
              ''      (explicitly empty) → cache off.
            When active, every successful pack-file locate causes the
            rest of that disc's data/ subtree to be copied into the
            cache.  Subsequent packs from the same disc are served from
            local storage; the disc-swap count drops from O(N_blobs)
            to O(N_discs).  A data disc that tier 1 finds for the first
            time is copied at once, even before one of its packs is
            needed, so no disc has to go back in later.  The copy
            prints how many MB are done, and is skipped when the
            cache's drive lacks room for the disc plus 5% of the
            drive (at most 1 GB) to spare (#634; before rc7: when the
            drive was under 10% free).
  Why:      Opt-OUT.  The v3 blind run took 16 disc swaps for 3 needed
            discs without the cache.  Forgetting this knob means the
            heir swaps discs 3-16× more often than necessary —
            a silent penalty that accumulates to hours of human time
            and risks disc handling errors.  Anyone short of disk space
            who cannot afford the cache can explicitly set
            LCSAS_PACK_CACHE_DIR='' to turn it off.
  Windows:  restore.bat honours it too (since rc6, #610).  Unset, it
            uses the pack-cache folder in the tools folder (see
            LCSAS_TOOLS_DIR), which outlives a restore that stopped,
            so carrying it on does not ask for those discs again.  It
            makes the folder and checks it is there before tier 1
            starts, and removes it after a successful restore (a folder
            you named yourself is kept).  cmd cannot hold an empty
            variable, so the '' form does not exist there: name another
            folder instead.  Without a working cache folder restore.bat
            does not pass --mount-parent either, because tier 1 would
            then open a catalog.db on a disc in place, and that disc
            could not come out of the drive.

LCSAS_INTERACTIVE
  Default:  unset → auto  (opt-in)
  Since:    rc6 (#617)
  Read by:  restore.sh and restore.bat (both pass it to tier 1 as
            --interactive)
  What:     restore.bat passes it to tier 1 as --interactive on, off
            or auto; any other value is ignored.  auto (tier 1's own
            default) asks at the disc-swap prompt only when its input
            is a console window.  on asks even when the answers come
            through a pipe, as in the windows-e2e single-drive leg and
            the wine single-drive test.  off never asks: a pack that is
            on no inserted disc fails at once.  restore.sh passes it to
            tier 1 the same way (since rc6, #617) and prints a line
            when it ignores a value.  restore.sh's own extra questions
            follow it too: the newest data disc, the check that asks a
            typed password again, and "Restore another backup set?"
            are asked on auto only when stdin is a terminal, on on
            always (a test rig answers them through a pipe), never on
            off.  So a piped or scripted run never waits for them.
            restore.bat's own questions do not follow it: it does not
            test for a console, so it asks them whatever the value
            (LCSAS_NEWEST_DISC_PROMPT=0 and LCSAS_ANOTHER_SET=0 turn
            off the two extra ones).
  Why:      Opt-in.  auto is right for a person at a console; the knob
            lets a test harness play that person at the disc prompt.

LCSAS_NEWEST_DISC_PROMPT
  Default:  unset → 1  (opt-out / default ON)
  Since:    rc6 (#605)
  Read by:  restore.sh and restore.bat
  What:     Run off the META disc on a terminal with no data disc in
            yet (relocated off the disc, or with LCSAS_META_DISC set;
            not for a copy of the META disc run where it is),
            restore.sh first asks the reader to take the META disc
            out and put in the NEWEST data disc (the latest year, then
            the highest number in its label, read from the disc's
            VOLUME_INFO.txt, never the drive's 16-character name for
            it).  That disc's copy of each backup set it holds (its
            snapshots and index) is the one used, and refreshes the
            tools folder's copy.  0 skips the question: the discs
            mounted now are used, else the copies on the META disc.
            Answering S at the question does the same; Q stops (exit
            65).  resume.sh and the next-set run set it to 0.
            The META disc's copies may lack the latest backups; and
            when the META disc was made after the newest data disc, its
            latest snapshot can need packs that are on no disc yet, so
            tier 1 then asks for a disc that does not exist.
  Windows:  restore.bat, run from a META disc (or relocated from one)
            with no data disc in any drive, first asks for the NEWEST
            data disc: the latest year, then the highest number, read
            from the label in its VOLUME_INFO.txt.  That disc's
            snapshots\ and index\ then replace the META disc's copies
            in the tools folder (keys\ from both; a set only on the
            META disc keeps its copy), and its catalog.db is the one
            used.  With data discs in at the start there is no
            question either: the newest of them is used.  The question
            is not asked when carrying on a stopped restore.  It is
            also asked from a copy of the META disc that can be
            written to (a USB stick): its merged copies then go in the
            tools folder's in-place\ folder.  It does not follow
            LCSAS_INTERACTIVE.  S skips it, Q stops (exit 65), and
            after five ENTERs with no data disc found it goes on with
            the META disc's copies (cmd cannot tell an empty answer
            from the end of the input).
  Why:      Opt-OUT.  The META disc's copy can be older than the newest
            data disc, and a set added after the META disc was made is
            not on it at all, so "latest" would quietly be older (#605).
            The knob is for test rigs and for a reader who knows the
            META disc is current.

LCSAS_ANOTHER_SET
  Default:  unset → 1  (opt-out / default ON)
  Since:    rc6 (#609)
  Read by:  restore.sh and restore.bat
  What:     After a restore that succeeds, when the discs hold more
            than one set and someone can answer (see
            LCSAS_INTERACTIVE), restore.sh asks "Restore another backup
            set from these discs? [y/N]".  y asks for the folder and
            starts again at the set list, reusing the tools folder and
            its pack cache; N ends the run and deletes the tools
            folder.  0 never asks.  restore_auto.sh sets it to 0.
            The next set's password is asked for: LCSAS_PASSWORD,
            LCSAS_PWFILE (--key) and LCSAS_SHARES_DIR are for the
            first set only.  Q at the next set list ends the run with
            0, as N does.
  Windows:  restore.bat asks it after a good restore of an archive
            with more than one backup set.  Yes goes back to the menu,
            with the tools folder, the pack cache and the catalog copy
            as they are; only no (or the end of the input) ends the
            run and lets the tools folder be deleted.  It asks for
            the set first and then the folder, whose default is
            Documents\restored-<name>; restore.sh asks for the folder
            first (default <target>-2).  It does not follow
            LCSAS_INTERACTIVE.
  Why:      Opt-OUT.  Restoring a second set (documents, then photos)
            would otherwise mean the META disc and the copy again.

LCSAS_TOOLS_DIR
  Default:  unset → $HOME/lcsas-restore-tools; on Windows
            %LOCALAPPDATA%\LCSAS-restore  (opt-out / default ON)
  Since:    rc6 (#609)
  Read by:  restore.sh and restore.bat
  What:     The tools folder restore.sh keeps a restore's own files in.
            Run off the META disc, it copies there: itself, this
            computer's binaries (bin/<triple>/ only), the docs and the
            disc's metadata/ folder; then it runs from the copy, so the
            disc can come out of the drive.  The pack cache, a copy of
            the catalog (tier 1 never gets a catalog.db on a disc) and
            resume.sh live there too.  resume.sh (mode 700) carries a
            stopped restore on with no META disc; it holds the set's id,
            the target and the settings, NEVER the password.
            The folder is removed after a restore that succeeds, once
            the reader declines another set, and kept after any other
            exit: a wrong password, q at the disc prompt (exit 75),
            Ctrl-C (130) or TERM (143).  The next run
            from the same META disc reuses the copy; a copy made by a
            different restore.sh is replaced (its pack cache is kept
            only when both come from the same build).  restore.sh
            writes the file .lcsas-restore-tools in a folder it uses,
            and later uses only an empty folder or one with that file.
            A folder that already holds other files is never used or
            deleted, and restore.sh falls back to a temporary folder,
            as it does when there is no $HOME.  Run off the META disc
            (relocated), that temporary folder becomes the tools
            folder: a stopped restore carries on from it with the
            resume.sh the script prints, until the folder is cleared
            (most systems empty /tmp at power-off).  Run in place, the
            run's own files go to a temporary folder that is deleted
            when it exits, so a stopped restore cannot be carried on.
            Run off the META disc, the programs run from the tools
            folder, so it must allow that (a FAT32 USB stick as a
            desktop mounts it does not); otherwise restore.sh falls
            back the same way.  On a live USB stick $HOME is in
            RAM: the folder is lost at power-off, and restore.sh says
            so.
  Windows:  restore.bat copies itself into it from a disc, with this
            computer's programs (bin\<triple>\ only),
            RECOVER_WINDOWS.txt, the backup sets' metadata, a copy of
            the catalog, the pack cache, resume.cfg and "Resume LCSAS
            restore.bat" (also put on the Desktop).  The folder stays
            until a restore has finished (exit 0) and the reader says
            no to another set, and is then deleted
            with the Desktop launcher; after a stop (exit 75, q at a
            disc box) or any other failure it stays, and the launcher
            carries the restore on with no META disc.  resume.cfg
            names the backup set, the restore folder and the drive
            letters, never the password.  A folder made by the very
            same restore.bat (compared with fc /b) from the very same
            META disc (its volume_info.json "created_at", kept in
            archive.txt) is used as it is; any other is replaced,
            keeping its pack cache only when its lcsas-restore.exe is
            the very same.  Since the tools folder is deleted at the
            end, restore.bat uses only a folder that is new, empty, or
            its own (it writes .lcsas-tools there first, a different
            name from restore.sh's); any other
            folder, and a whole drive (E:\), is refused with exit 1
            before anything in it changes.  That holds for every run,
            the default folder included.  A run that does not relocate
            (LCSAS_NO_RELOCATE=1, or a META disc copied to a folder or
            a USB stick, which can be written to) keeps its pack cache,
            catalog copy and merged metadata in the folder's
            in-place\ subfolder, removed after exit 0, so a stopped
            restore waiting in the folder is left as it is.
            Not %TEMP%: Disk Cleanup and Storage Sense empty it.
  Why:      Opt-OUT.  Without it a stopped restore meant the META disc,
            the copy and every disc again (#609).  Point it elsewhere
            when $HOME is small or in RAM, e.g. at a USB disk, or on
            Windows when C: is short of space.

LCSAS_DRAIN_CHUNK_PACKS
  Default:  0  (opt-in / default OFF)
  Since:    Phase 25
  Read by:  tier 1, so it works with restore.sh and restore.bat
  What:     Limits how many pack files are copied per drain_disc() call.
            0 (default) → drain the entire disc data/ subtree in one
            call (safe, but can stall for 8-40 minutes on a slow
            optical drive ~10 MB/s before the next pack lookup proceeds).
            N > 0 → copy at most N packs per call, then return.  The
            next drain_disc() call resumes automatically (already-cached
            packs are skipped via stat, so re-entry is cheap).  Set to
            100-500 when working with slow optical drives to keep the
            restore interactive between drain calls.
  Why:      Opt-IN.  Changing the default would change observable timing
            behavior: existing scripts and people that rely on the
            disc being fully drained after the first pack hit would see
            a different pattern.  Draining in steps is an explicit
            trade-off between restore interactivity and disc-read
            continuity; anyone who wants it must opt in.

LCSAS_MAX_JSON_MIB
  Default:  256  (opt-in override; default ceiling always active)
  Since:    Phase 26 (T1C-01)
  Read by:  tier 1, so it works with restore.sh and restore.bat
  What:     Maximum token-buffer memory, in MiB, that tier-1 will
            allocate to parse any single JSON structure (index file,
            snapshot file, or tree blob).  Tier-1 parsing is otherwise
            size-adaptive — the buffer grows on demand — so ordinary
            repositories never approach this ceiling.  A structure that
            needs more fails LOUD (names the file, points at tier-2);
            it is never silently skipped.  Lower it on a memory-starved
            32-bit host (e.g. armv7); raise it only if a genuinely huge
            structure legitimately needs more than 256 MiB of tokens.
  Why:      Opt-IN override of an always-safe default.  The 256 MiB
            ceiling bounds heap growth so a pathological or malicious
            JSON blob can't exhaust a small address space; overriding it
            is an escape hatch, not a routine knob.

LCSAS_MAX_TREE_DEPTH
  Default:  1000  (opt-in override; default cap always active)
  Since:    Phase 26 (T1C-04)
  Read by:  tier 1, so it works with restore.sh and restore.bat
  What:     Maximum directory-tree recursion depth tier-1 will walk.
            Tier-1 descends subtrees on the C stack (~6 KB per level);
            1000 levels ~= 6 MB, inside the default 8 MB stack ulimit.
            A tree deeper than this fails LOUD with a named error
            ("directory tree deeper than N levels at <path>") instead of
            crashing with a stackless SIGSEGV.  Raise it ONLY together
            with 'ulimit -s unlimited' to restore a genuinely deeper
            layout; otherwise prefer tier-2 (rustic).
  Why:      Opt-IN override of an always-safe default.  Before the cap a
            ~1300+ level tree killed the process by signal with zero
            diagnostic — indistinguishable from "the software is broken"
            to a non-technical heir.  The cap converts that into an
            actionable error that can be worked around.  Overriding it
            is an escape hatch, not a routine knob.

LCSAS_TIER_FALLBACK
  Default:  0  (opt-in / default OFF)
  Since:    Phase 24
  Read by:  restore.sh only
  What:     0 (default) → restore.sh runs tier 1 and exits with its
            exit code; a tier-1 crash is not followed by another tier.
            (It runs tier 1 rather than exec()ing it, so its exit
            handler can still delete the temporary password file,
            #363.)
            1 → run each non-last tier as a subprocess; fall through to
            the next tier (tier 2, then tier 3) on non-zero exit.
            Never after tier-1 exit 77 (wrong password) or 75 (q at
            the disc prompt): those stop the run either way.
  Windows:  restore.bat does not read it.  It always tries tier 2
            after a tier-1 failure, but only for a backup set whose
            folder holds its own data\ (rustic-static cannot ask for
            discs), and never after exit 75 or 77.  A set read from
            the discs stops after tier 1 and keeps the tools folder.
            That check sits inside the tier-1 step, so when
            lcsas-restore.exe is missing (say, quarantined by
            antivirus) in a run that does not relocate, restore.bat
            goes straight to tier 2 whatever the set, and tier 2
            fails for a set read from the discs.  restore.bat has no
            tier 3.
  Why:      Opt-IN.  The default (tier 1 only, its exit code returned)
            preserves the bare-minimum restore story: tier 1 IS the
            restore path, and failures must surface immediately so you
            know tier 1 is broken.  Silent fallback could mask a
            tier-1 regression, giving false confidence that an archive
            can be restored when the primary path is actually broken.
            LCSAS_TIER_FALLBACK=1 is an explicit opt-in for anyone
            who already knows tier 1 is broken and wants the cascade
            to walk for them.

LCSAS_ALLOW_PYTHON_TIER
  Default:  1  (opt-out / default ON)
  Since:    Phase 20
  Read by:  restore.sh only (restore.bat never starts tier 3)
  What:     1 (default) → tier 3 (the Python reader) is a reachable
            fallback when tiers 1 and 2 are both absent or failed.
            0 → stop the cascade after tiers 1/2; never invoke Python.
  Why:      Opt-OUT.  Tier 3 is the last-resort safety net; disabling
            it without an explicit choice removes the only non-binary
            recovery tier.  Environments that ban Python
            entirely (air-gapped kiosks) can set this to 0.

LCSAS_PROGRESS
  Default:  unset → ON (opt-out / default ON)
  Since:    Phase 22
  Read by:  tier 3 only
  What:     Controls the periodic progress output on stderr of the
            tier-3 Python reader ("N/M files, X MB").
            Set LCSAS_PROGRESS=0 to silence it.  Any other value
            (including unset) enables it.  Tier 1 does not read this
            variable: lcsas-restore always prints its
            "[lcsas-restore] progress: N/M blobs, X MB" lines.
  Why:      Opt-OUT.  On a slow disc (~1 MB/s) a silent restore is
            indistinguishable from a frozen process.  Forgetting this
            knob means you cannot tell if the restore is
            proceeding or stuck.  The only reason to silence it is in
            machine-parseable log pipelines; that requires explicit opt.

LCSAS_NO_RELOCATE
  Default:  0  (opt-in / default OFF)
  Since:    Phase 20
  Read by:  restore.sh and restore.bat
  What:     1 → skip the relocation step.  Normally restore.sh
            detects when it is running off a read-only optical medium
            and copies itself + the recovery binaries to the tools
            folder (LCSAS_TOOLS_DIR) before exec()ing the copy.  This
            lets you eject the meta disc and reuse the drive for data
            discs.
            0 → perform relocation when the medium appears read-only.
  Windows:  restore.bat reads it too: 1 skips the copy into the tools
            folder, and the script runs where it is.  It still keeps
            its pack cache, its catalog copy and the metadata it
            merges in the tools folder's in-place\ folder, removed
            after a restore that succeeds, and writes no resume.cfg
            or "Resume LCSAS restore.bat".
  Why:      Opt-IN.  The relocation is a safety behavior; disabling it
            is only appropriate in test / development environments
            (e.g., running restore.sh from a source checkout on a
            writable disk).  Accidentally disabling it during a real
            single-drive restore holds the meta disc open and prevents
            ejecting.

LCSAS_ALLOW_NO_PACK_SEARCH
  Default:  0  (opt-in / default OFF)
  Since:    Phase 23
  Read by:  restore.sh only
  What:     1 → suppress the "no data discs detected" hard error.
            Normally restore.sh aborts before asking for a password if
            no mounted disc contains a data/ directory, because the
            binary will fail anyway and the early abort gives a more
            actionable message.
            0 → enforce the pre-flight check.
  Why:      Opt-IN.  The check exists precisely because missing it
            leads the heir to type a password and wait before
            seeing the inevitable "no packs found" failure.  The bypass
            is for test fixtures, initramfs environments, and scripted
            pipelines that mount data discs between the script setup
            step and the binary invocation.

LCSAS_ALLOW_TMPFS_TARGET
  Default:  0  (opt-in / default OFF)
  Since:    2026-06 audit (BOOT-05)
  Read by:  restore.sh only
  What:     1 → skip the interactive "Continue restoring into RAM
            anyway? [y/N]" confirmation when the target directory sits
            on a RAM-backed filesystem (tmpfs/ramfs).  The warning
            banner still prints to stderr.
  Why:      Opt-IN.  The prompt protects a human heir from restoring
            into memory ("restore complete" → poweroff → everything
            gone).  Suppressing it is for scripted-but-interactive
            environments that have already accepted that trade-off.

LCSAS_FORBID_TMPFS_TARGET
  Default:  0  (opt-in / default OFF)
  Since:    2026-06 audit (BOOT-05)
  Read by:  restore.sh only
  What:     1 → refuse to restore into a RAM-backed (tmpfs/ramfs)
            target directory even when no TTY is attached.  The
            default non-interactive behavior is warn-and-continue so
            existing automation (blind drills, test harnesses) that
            legitimately restores to tmp paths keeps working.
  Why:      Opt-IN.  Hard-failing by default would break legitimate
            scripted restores to tmpfs paths; automation that must
            never write a restore into RAM sets this explicitly.

LCSAS_SKIP_SPACE_CHECK
  Default:  0  (check ON / opt-out)
  Since:    2026-06 audit (FMA-09)
  Read by:  restore.sh and restore.bat (since rc8, #660)
  What:     1 → skip the free-space preflight restore.sh runs before
            any password or disc prompt.  The check derives the
            archive size from the freshest reachable catalog.db (via
            a sqlite3 CLI when present, else the tier-1 binary's
            --list-pending-packs total) and refuses with the exact
            required-vs-available numbers when either the target
            directory or the pack-cache filesystem is too small.
            Each needs about the archive size, so when the two share
            a filesystem (the default) it needs the sum (#660).  What
            an earlier run wrote counts: the packs in the cache, and
            the files in a target that holds the restore marker.
            When the size cannot be derived the check silently skips.
  Windows:  restore.bat makes the same check (since rc8, #660), after
            the catalog copy and before the password.  The size is
            always the tier-1 --list-pending-packs total (every set in
            the archive), the free space comes from `dir`, and "the
            same filesystem" means the same drive letter.  When the
            discs hold more than one backup set, a short drive asks
            "Carry on anyway? [y/N]" (y goes on) rather than stopping,
            as the size may be far above the chosen set's.  Set it in a
            Command Prompt (set LCSAS_SKIP_SPACE_CHECK=1) and run
            restore.bat from there.
  Why:      Opt-OUT.  Forgetting the check means discovering a
            too-small disk via ENOSPC after hours of disc swapping —
            the worst possible point.  The bypass exists for
            restoring a SUBSET (one small snapshot of a large
            archive) where the whole-archive estimate is a
            deliberate overestimate.

LCSAS_CHECK_DISC_AUTOFIX
  Default:  0  (ask on a terminal; refuse without one / opt-in)
  Since:    2026-06 audit (FMT-01, --check-disc)
  Read by:  restore.sh and restore.bat (--check-disc only)
  What:     1 → when `restore.sh --check-disc` (or `restore.bat
            --check-disc`) finds damage in a disc image, repair it
            using the burned RS03 ECC parity WITHOUT the interactive
            "Repair it now? [y/N]" confirmation.  With no terminal
            and this unset, restore.sh refuses to write and exits 1.
            restore.bat always asks; an empty answer, or the end of
            the input, leaves the image as it is (exit 1).
  Why:      Opt-IN.  Repair rewrites the image file; an unattended
            run must explicitly accept that risk.

LCSAS_FORCE_NONEMPTY_TARGET
  Default:  0  (confirm on a terminal; refuse without one / opt-in)
  Since:    2026-06 audit (UX-07)
  Read by:  restore.sh and restore.bat
  What:     1 → skip the "target folder already contains files that
            do not look like a previous LCSAS restore" overwrite
            guard in restore.sh / restore.bat.  Interactively the
            guard asks you to type YES; non-interactively it refuses
            (exit 65) unless this is set.  (A hidden marker file,
            .lcsas-restore-marker, makes re-runs into the same restore
            target silent either way.)  restore.sh's marker names the
            backup sets restored into the folder, so restoring another
            set into it warns too.
  Windows:  restore.bat asks for YES whether or not a person is
            there; any other answer, or the end of the input, stops
            with exit 65.  Its marker is empty, so it does not warn
            about another set restored into the same folder.
  Why:      Opt-IN.  Restoring over unrelated existing files can
            silently overwrite them; scripted runs must opt in.

LCSAS_KEYSHARE_PASSPHRASE
  Default:  unset (empty passphrase)
  Since:    Key escrow (C5, 2026-05)
  Read by:  lcsas-keyshare, so it works with restore.sh and
            restore.bat when they combine share cards
  What:     Passphrase for SLIP-0039 share combination, read by the
            tier-1 `lcsas-keyshare` combiner when no --passphrase
            flag is given.  Only relevant for splits created with a
            non-default passphrase.
  Why:      Opt-in — same credentials reasoning as LCSAS_PASSWORD:
            secrets enter the environment only by explicit action.

────────────────────────────────────────────────────────────────────
INTERNAL VARIABLES (DO NOT SET)
────────────────────────────────────────────────────────────────────

LCSAS_RELOCATED
  Internal sentinel set by restore.sh on re-exec after relocation to
  the tools folder (resume.sh sets it too), and by restore.bat when it
  runs its copy in the tools folder (also from resume.cfg when "Resume
  LCSAS restore.bat" carries a restore on).  Its value is the meta
  disc's original mount path or drive letter.  Not a knob; do not set
  manually.  (restore.sh's relocation also exports LCSAS_TOOLS_DIR with
  the folder it used.)

LCSAS_RESUME
  Internal: resume.sh sets it to 1 when the tools folder holds the
  copy of the set's snapshots the stopped run used.  The resumed run
  then uses that copy (and skips the newest-disc metadata refresh),
  so "latest" is the same snapshot as before the stop, whatever data
  disc is in the drive by then.  Not a knob; do not set manually.

LCSAS_ANOTHER_PASS
  Internal: restore.sh sets it to 1 when it starts again for the
  next backup set after "Restore another backup set? [y/N]".  Q
  (or the end of the input) at that run's list of sets then means
  no other set: the run ends with 0 and the tools folder goes, as
  in restore.bat.  Not a knob; do not set manually.
