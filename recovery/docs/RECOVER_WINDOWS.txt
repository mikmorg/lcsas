LCSAS RESTORE ON WINDOWS -- STEP BY STEP
========================================

WHO THIS IS FOR

You are running Windows 10 (version 1709 / October 2017 or later)
or Windows 11.  You have inherited a collection of LCSAS discs and
you want to read the files on them.  You have the password for the
archive, or enough of its share cards.

WHY 1709?

  Our prebuilt lcsas-restore.exe imports the Windows Universal C
  Runtime (UCRT, the api-ms-win-crt-*.dll family).  UCRT ships in
  the OS starting with Windows 10 1709.  Windows 7 SP1 / 8 / 8.1
  also have it IF Windows Update KB2999226 (Sep 2015) was installed;
  most patched systems do.

  Windows XP / Vista / unpatched 7-8 cannot run the bundled binary.
  For those systems, see "ON OLDER WINDOWS" below.

You do NOT need:

  * Admin rights.
  * To install WSL, Cygwin, or any developer tools.
  * To re-partition your disk.
  * To restart or boot the computer in any special way.  (LCSAS
    discs are NOT bootable; you read them from inside Windows.)

You DO need:

  * A USB Blu-ray reader (or any optical drive that reads the disc
    format your archive uses).
  * The password.

────────────────────────────────────────────────────────────────────
QUICK START (90 SECONDS)
────────────────────────────────────────────────────────────────────

  1. Plug in your USB Blu-ray reader.
  2. Insert the meta disc (labelled "LCSAS_META").  If you have
     several, use the newest; if that fails, use the one burned
     closest in date to your data discs.
  3. Open File Explorer.  The disc should appear under "This PC" as
     a drive (typically D:, E:, or F:).
  4. Open the disc.
  5. Double-click  restore.bat.
  6. A black console window opens.  Do not click inside it while
     the restore runs (see "A CLICK IN THE WINDOW PAUSES THE
     RESTORE" below).  It first copies its programs to this
     computer (see "THE COPY ON THIS COMPUTER" below).  Then it
     asks, one question at a time:
        - for your newest data disc: take the meta disc out, put
          that disc in, and press Enter (see "THE NEWEST DATA DISC
          FIRST" below).
        - which backup set to restore, if the archive has more
          than one: type its number and press Enter.
        - for the restore folder: press Enter to accept the default
          (Documents\restored), OR type a folder of your choosing,
          with its drive (for example E:\restored).
        - for the password: type it and press Enter.  If the
          password of that set is split into share cards, it asks
          for the cards instead (see "SHARE CARDS" below).
  7. Wait.  When the script says "Restore complete", the files are
     in the folder you chose.  If the archive has more than one
     backup set, it then asks whether to restore another one.

If you have multiple discs, the script will tell you when to swap.
If you stop, or the window closes, you can carry on later without
the meta disc: see "STOPPING AND CARRYING ON" below.

────────────────────────────────────────────────────────────────────
A CLICK IN THE WINDOW PAUSES THE RESTORE (QuickEdit)
────────────────────────────────────────────────────────────────────

The script says this first, before anything else:

     NOTE: do not click inside this window while the restore runs.
     A click selects text and PAUSES the restore: the window title
     then starts with "Select".  If that happens, press Esc or
     right-click inside the window, and the restore carries on.

Windows 10 turns on a console setting called QuickEdit.  A click or
a tap inside the black window starts selecting text, and while text
is selected Windows stops the restore from writing to the window,
so it waits.  Nothing is lost: press Esc, or right-click, and it
goes on where it was.  The script does not change this setting for
you.

────────────────────────────────────────────────────────────────────
THE COPY ON THIS COMPUTER (the tools folder)
────────────────────────────────────────────────────────────────────

You do NOT need two Blu-ray drives.  Before the first question,
restore.bat copies what this computer needs from the meta disc into
a folder on this computer, the tools folder:

     %LOCALAPPDATA%\LCSAS-restore
     (usually C:\Users\<you>\AppData\Local\LCSAS-restore)

and runs that copy.  From then on nothing on the meta disc is in
use, so it can come out of the drive.  The copy is small, a few MB:
the three restore programs for Windows (lcsas-restore.exe,
lcsas-keyshare.exe, lcsas-ecc.exe), this guide, and the index of
each backup set (the metadata folder).  The script names each file
as it copies it:

     [lcsas-restore] copying the restore programs for this computer to
                     C:\Users\<you>\AppData\Local\LCSAS-restore
                     so that the META disc can come out of the drive:
                       recovery\bin\x86_64-pc-windows-gnu\lcsas-restore.exe
                       ...
     [lcsas-restore] copied recovery files to C:\Users\<you>\AppData\Local\LCSAS-restore

The tools folder stays until the restore has finished, and is then
deleted.  If a tools folder from an earlier run is there and was
copied from this same meta disc, the script uses it as it is
("using the recovery files already copied to ...").  One copied
from another meta disc, or by another version, is replaced.  To
put the tools folder somewhere else, set LCSAS_TOOLS_DIR to an
empty or new folder before you start (see ENV_VARS.txt).  Because
the script deletes the tools folder at the end, it will not use a
folder that already holds other files, or a whole drive such as
E:\: it stops with an error before it changes anything there.

────────────────────────────────────────────────────────────────────
THE NEWEST DATA DISC FIRST
────────────────────────────────────────────────────────────────────

The meta disc knows your backups only as they were when it was
burned.  Every data disc knows them as they were when that disc was
burned, so the newest data disc knows the latest backup, and any
backup set added after the meta disc was made.  When no data disc
is in a drive yet, the script asks for that disc first:

     Take the META disc out and put in your NEWEST data disc: the one
     with the latest year, and then the highest number, e.g.
     LCSAS_CD700_2026_0002.  File Explorer shows only the first 16
     characters of the label; the full label is printed on the disc.

     Press ENTER when it is in; S then ENTER to skip (use the copies
     on the META disc); Q then ENTER to quit.

Take the meta disc out (nothing on it is in use any more), put in
the data disc whose label has the latest year and then the highest
number, wait until File Explorer shows it, and press Enter.  The
script prints the label it read from the disc, for example:

     [lcsas-restore] newest data disc: LCSAS_CD700_2026_0002 in drive D:

Check it against the label printed on the disc.  File Explorer
shows only "LCSAS_CD700_2026" for every CD of a year, so the script
reads the full label from the file VOLUME_INFO.txt on the disc.  If
the disc in the drive is not a data disc of the archive, the script
says so and asks again.

The script then uses that disc's list of backups and its catalog,
which says which disc holds what.  Leave the disc in the drive: the
restore reads from it first.

S skips this step.  The restore then uses the copies on the meta
disc, which may lack the latest backups.  Worse, if the meta disc
was made AFTER your newest data disc, its latest backup can need
files that are on no disc yet: the restore then asks for a disc
that does not exist.  Skip only when you have no data disc at
hand.

If data discs are already in their drives when you start (a
computer with several drives), the script does not ask: it uses the
one with the newest label.

────────────────────────────────────────────────────────────────────
SWAPPING DISCS
────────────────────────────────────────────────────────────────────

When the restore needs a data disc, it shows a box like this:

    Pack 4f3e2a1b9c8d0e7f... is required for the next file.
    It is on any disc labelled:
      LCSAS_BD25_2026_0003

Take the disc that is in the drive out, put in the disc the box
names, and press Enter.  Use the same drive the meta disc was in.

The box names the disc from the catalog of the newest data disc.
If you skipped that disc (S), the first box may not name a disc yet.
Then put in your newest data disc: the latest year, then the
highest number.  Every data disc carries a catalog, so from then on
the box names the disc it needs.  A wrong disc does no harm: the box
just asks again.

The first time the restore reads from a data disc, it copies all of
that disc's packs to this computer, so you put each disc in about
once.  The copy sits in the tools folder (usually on drive C:) and
is deleted when the restore has finished.

────────────────────────────────────────────────────────────────────
STOPPING AND CARRYING ON
────────────────────────────────────────────────────────────────────

To stop, type Q and press Enter at a disc box.  The script says:

     The restore stopped before it finished (code 75).

     The files restored so far are kept in:
       C:\Users\<you>\Documents\restored

     To carry on, double-click "Resume LCSAS restore.bat" on
     your Desktop, or type this command:
       "C:\Users\<you>\AppData\Local\LCSAS-restore\Resume LCSAS restore.bat"

The files restored so far stay in the folder you chose, and the
tools folder stays too, with the disc copies made so far.

To carry on, later or on another day, double-click "Resume LCSAS
restore.bat" on your Desktop (the same file is in the tools
folder).  You do NOT need the meta disc for that, and nothing is
copied again.  It carries on with the same backup set, into the
same folder, and looks in the same drives, even one that is empty
when you start it.  It asks for the password again: the password is
never saved.  Then put in the disc each box names.  Files that are
already restored are skipped.

The same works if the window was closed, or the computer was
restarted, once you had answered the question about the restore
folder: the script makes "Resume LCSAS restore.bat" right after
that question, before it asks for the password.  If the window
closed before then, there is nothing to carry on yet: run
restore.bat from the meta disc again.  Running restore.bat from
the meta disc again always works too: it asks the questions again
and uses the tools folder that is already there.

When the restore has finished, and you have said no to restoring
another backup set (see "MORE THAN ONE BACKUP SET"), the script
deletes the tools folder and "Resume LCSAS restore.bat" (both
copies).  To give up a restore
you do not want to finish, delete the folder
%LOCALAPPDATA%\LCSAS-restore and the file on your Desktop yourself.

────────────────────────────────────────────────────────────────────
FILES LARGER THAN 4 GiB (multi-extent ISO 9660 limitation)
────────────────────────────────────────────────────────────────────

Windows' built-in CDFS driver -- the one behind File Explorer's
disc view and PowerShell's Mount-DiskImage -- cannot reassemble a
single file larger than 4 GiB (precisely, 4 GiB - 2 KiB).  ISO 9660
stores such a file as multiple "extents", and the native Windows
driver reads only the first one: the file appears TRUNCATED with no
error message.

LCSAS refuses to master an ISO image containing a file this large
(the ISO build aborts with an "OversizeFileError" naming the file),
so a disc produced by an up-to-date LCSAS should never trigger
this.  But if you are reading an older disc and a restored file
looks truncated AND the binary did NOT report a hash mismatch,
suspect this limitation.

WORKAROUND: do not read the over-large file through the mounted
disc.  Instead copy the entire .iso image to a local disk and
extract it with 7-Zip (https://www.7-zip.org), which reassembles
multi-extent files correctly.  Right-click the .iso in 7-Zip File
Manager -> Extract, then run restore.bat against the extracted
folder instead of the mounted drive.

────────────────────────────────────────────────────────────────────
CHECK THE BINARY BEFORE RUNNING IT (optional, for the cautious)
────────────────────────────────────────────────────────────────────

Every file on the disc has a SHA-256 hash recorded in
recovery\MANIFEST.sha256.  Before double-clicking restore.bat, you
can check both the script and the binary against the manifest
using Windows' built-in certutil tool.  No third-party software
required.

  STEP 1.  Open a Command Prompt and change to the disc.

      D:                              (or whichever drive letter)
      cd D:\

  STEP 2.  Compute the SHA-256 of restore.bat and lcsas-restore.exe.

      certutil -hashfile restore.bat SHA256
      certutil -hashfile recovery\bin\x86_64-pc-windows-gnu\lcsas-restore.exe SHA256

  STEP 3.  Look up the expected hash in recovery\MANIFEST.sha256:

      findstr /C:"restore.bat" recovery\MANIFEST.sha256
      findstr /C:"lcsas-restore.exe" recovery\MANIFEST.sha256

  The two values for each file must match.  If findstr finds no
  line for the file, you are probably looking at the wrong path --
  check recovery\bin\ for the actual folder name.  A hash that
  EXISTS in the manifest but differs from certutil's output means
  corruption or tampering -- do not run that binary.

────────────────────────────────────────────────────────────────────
SMARTSCREEN WARNING ("Windows protected your PC")
────────────────────────────────────────────────────────────────────

When you double-click restore.bat for the first time, Windows
SmartScreen may show:

    Windows protected your PC
    Microsoft Defender SmartScreen prevented an unrecognized app
    from starting.

This is expected: the recovery tools are unsigned (signing
certificates expire on a 1-3 year cycle and are incompatible with
long-term archival).

To proceed:

  1. Click "More info".
  2. Click "Run anyway".

If your antivirus quarantines lcsas-restore.exe, restore it from
the antivirus's quarantine UI.  The binary's SHA-256 is recorded in
recovery\MANIFEST.sha256 on the disc; you can check it by hand:

    certutil -hashfile recovery\bin\x86_64-pc-windows-gnu\lcsas-restore.exe SHA256

────────────────────────────────────────────────────────────────────
THE PASSWORD
────────────────────────────────────────────────────────────────────

The script asks for the password of the backup set you chose:

     Password:

Type it and press Enter.  Before the restore starts, the script
tries the password.  If it is wrong, it says so:

     That password is wrong: it does not open the backup set
     Family documents.

and asks again.  An empty answer asks again too.  To stop, type Q
and press Enter: nothing is restored (exit code 77).

THE PASSWORD IS VISIBLE WHILE YOU TYPE IT.  Plain CMD cannot hide
it; the script says so before it asks.  Make sure nobody can see
your screen.

To type it hidden, use Windows PowerShell (it comes with Windows 10
and 11).  Open PowerShell and run these lines.  They ask for the
password without showing it, write it to a file in your temporary
folder with no line break at the end, start the restore, and delete
the file afterwards:

    $s = Read-Host -AsSecureString -Prompt "Password"
    $b = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($s)
    $p = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($b)
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($b)
    $f = "$env:TEMP\lcsas-pw.txt"
    $u = New-Object Text.UTF8Encoding($false)
    [IO.File]::WriteAllText($f, $p, $u)
    $env:LCSAS_PWFILE = $f
    D:\restore.bat
    Remove-Item $f

(Replace D: with your disc's drive letter.)  These lines work in the
Windows PowerShell 5.1 that comes with Windows; they do not need
PowerShell 7.

The script reads the password from the file LCSAS_PWFILE names, byte
for byte, and does not ask for it.  Any file that holds only the
password will do, for example one on a USB stick:

    set LCSAS_PWFILE=E:\password.txt
    D:\restore.bat

LCSAS_PASSWORD holds the password itself instead of a file name
(LCSAS_PW, an older name, works too).  If the password from either
is wrong, the script says so and asks for it on the keyboard.

────────────────────────────────────────────────────────────────────
SHARE CARDS (SPLIT PASSWORDS)
────────────────────────────────────────────────────────────────────

Some archives split a backup set's password into N shares, one per
share card: any K of them rebuild it, and fewer than K reveal
nothing.  An archive may split some sets' passwords and not others.
PASSWORD_INFO.txt on any disc states, for each set, whether its
password was split, and the K and N.

When the set you chose is split, the menu says so, for example:

     [2] Holiday photos (password split: any 2 of 3 share cards)

and the script asks for the cards instead of the password:

     The password for Holiday photos is split into 3 share cards; you
     need any 2 of them (Split ID 01234).

     Share card 1 of 2: type all the words on one line, then ENTER
     (or Q to quit).
     Words of card 1:

Take any K cards whose "Split ID" is the one shown.  For each card,
type all its words on one line, in order, with a space between
them, and press Enter.  The first 4 letters of each word are enough.
The script checks each card on its own as you type it: if a word is
wrong, it names the word and asks for that card again.  When it has
K cards, it rebuilds the password with the bundled
lcsas-keyshare.exe and goes on.  Cards from another backup set, or
the same card typed twice, do not rebuild the password: the script
says so and asks for the cards again.

Each card you type is kept in a file of its own in %TEMP% only until
the password is rebuilt, and then deleted.  If you have already
rebuilt the password, type P instead of a card, and then the
password.

TO TYPE NO CARDS: put each card in a text file of its own, all in
one folder (a retyped card, or the card file as it was printed: its
other lines may stay in the file), and set LCSAS_SHARES_DIR to that
folder before you start.  More than K cards is fine.

    set LCSAS_SHARES_DIR=C:\Users\me\cards
    D:\restore.bat

IF THE MENU DOES NOT SAY THE PASSWORD IS SPLIT, but PASSWORD_INFO.txt
does (an older disc, for one), use LCSAS_SHARES_DIR as above, or
rebuild the password yourself and type it at the "Password:" prompt:

  STEP 1.  Gather any K share cards of that backup set (printed
           pages headed "LCSAS KEY SHARE" or "SHARE CARD"; each card
           names its set).  If you only have paper, retype each card
           into its own text file, e.g. C:\Users\me\card1.txt and
           C:\Users\me\card2.txt.

  STEP 2.  Open a Command Prompt at the meta disc root (e.g. D:)
           and run the bundled combiner:

               recovery\bin\x86_64-pc-windows-gnu\lcsas-keyshare.exe ^
                   C:\Users\me\card1.txt C:\Users\me\card2.txt

           It prints the password and nothing else.  Append
           " > C:\Users\me\repo.key" to the command to save it to
           a file instead, and use that file as LCSAS_PWFILE (see
           "THE PASSWORD" above).

  STEP 3.  Run restore.bat as normal and type the rebuilt password
           at its "Password:" prompt.

If lcsas-keyshare.exe will not run on your host, install Python 3
(see "MANUAL PYTHON RESTORE" below for the python.org steps) and
use the pure-Python fallback at the meta disc root:

               python D:\keyshare_combine.py ^
                   C:\Users\me\card1.txt C:\Users\me\card2.txt

Format + re-implementation details: docs/SHARE_FORMAT.md on the
meta disc.

────────────────────────────────────────────────────────────────────
MORE THAN ONE BACKUP SET
────────────────────────────────────────────────────────────────────

An archive can hold several backup sets, each with its own password
(for example "Family documents" and "Holiday photos").  The script
lists them by name and asks which one to restore:

     This archive contains more than one backup set:
        [1] Family documents
        [2] Holiday photos (password split: any 2 of 3 share cards)

     Type the number of the one to restore, or Q then ENTER to quit.
     Which one do you want to restore? [1]:

A set from an older disc shows a long code such as
3f9c2b71-8d4e-4a06-b5e1-7c0a9d2e6f48 instead of its name.  In a name,
each character other than A-Z, a-z, 0-9, space and . _ + , - shows
as "_", and a name with none of A-Z, a-z or 0-9 shows the code.

When a set has been restored, the script asks:

     Restore another backup set from these discs? [y/N]:

Type Y and press Enter to choose the next set from the same list.
The copy on this computer is kept, and so are the copies of the
discs read so far, so those discs are not asked for again.  The next
set goes into a folder of its own by default
(Documents\restored-<its name>).  Enter alone, or N, ends the run,
and only then is the tools folder deleted.

To choose a set without the menu, set LCSAS_REPO to its name or its
code before you start (see ENV_VARS.txt).

────────────────────────────────────────────────────────────────────
DESTINATION FOLDER NOTES
────────────────────────────────────────────────────────────────────

  * The default destination is %USERPROFILE%\Documents\restored,
    typically C:\Users\<you>\Documents\restored.

  * Choose a folder, not a whole drive.  To restore onto a USB
    drive E:, type a folder on it, such as E:\restored.  If you
    type just E:\ the script asks again.

  * Type the whole path of the folder, starting with its drive:
    C:\Users\<you>\restored, not just "restored" (the script asks
    again).  Q then Enter at this question stops the script;
    nothing is restored (exit code 65).

  * While it runs, the restore also keeps a copy of the packs of
    each data disc it has read, in the tools folder
    (%LOCALAPPDATA%\LCSAS-restore, usually on drive C:).  That needs
    free space too: about the size of those discs.  It is deleted
    when the restore has finished.

  * If the original archive has more data than you have free disk
    space, the restore will fail partway through.  restore.bat does
    not check this for you (restore.sh on macOS/Linux does), so check
    first.  Put the data disc whose label is newest (the latest
    year, then the highest number; its catalog is the fullest) in
    drive E:, open a Command Prompt at the META disc and run:

        recovery\bin\x86_64-pc-windows-gnu\lcsas-restore.exe ^
            --catalog E:\catalog.db --list-pending-packs

    Its last line reads "Total: N packs, X MB across M discs."  Make
    sure the destination drive has at least X MB free, as shown in
    File Explorer under "This PC".

  * Long paths: Windows historically limited paths to 260 characters.
    Modern Windows 10/11 supports longer paths if enabled in Group
    Policy.  Restored files with paths > 260 chars will fail to
    write.  Workaround: enable long-path support
    (Computer\HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\
     FileSystem\LongPathsEnabled = 1) or restore to a folder with a
    short root path like C:\r.

  * Symlinks in the original archive are NOT restored on Windows.
    Creating Windows symlinks requires the SeCreateSymbolicLink
    privilege which we do not request.  The corresponding restored
    paths will simply be missing.  Affected paths are reported on
    stderr.

  * Filename case: Windows is case-insensitive.  If the original
    archive contained two files differing only by case (foo.txt and
    FOO.TXT), only one will survive the restore.  This is rare in
    practice on archives created from Linux/macOS users' home dirs.

────────────────────────────────────────────────────────────────────
WHAT IF restore.bat DOES NOT RUN?
────────────────────────────────────────────────────────────────────

CASE A.  Double-click opens Notepad instead of running the script.
         File Explorer is set to "show extensions for known file
         types".  Right-click restore.bat -> Open with -> "Windows
         Command Processor".  Or open CMD/PowerShell and type
         `D:\restore.bat`.

CASE B.  The console window flashes and disappears.
         Open CMD/PowerShell first, navigate to the disc
         (`cd D:`), then run `restore.bat` so the error message
         stays on screen.

CASE C.  "lcsas-restore.exe is not recognized as an internal or
         external command."
         restore.bat looks for the .exe under
         recovery\bin\x86_64-pc-windows-gnu\.  If that path is empty
         on your meta disc, it was built without the Windows binary.
         Options:

           (a) Cross-build on another machine and copy the .exe in.
               From a Linux/macOS host with the LCSAS source:
                   cd recovery
                   make windows
                   cp bin/x86_64-windows/lcsas-restore.exe \
                      /path/to/disc/recovery/bin/x86_64-pc-windows-gnu/
               NOTE the two folder names differ on purpose:
               bin/x86_64-windows/ is the build-host output dir in
               the source tree; the disc stores binaries under the
               rust target triple, bin\x86_64-pc-windows-gnu\.

           (b) Use WSL.  Install WSL2 from the Microsoft Store (no
               admin needed in recent Windows versions), then:
                   wsl
                   sh /mnt/d/recovery/scripts/restore.sh /mnt/d ~/restored
               (replace /mnt/d with your disc mount point inside WSL).

           (c) Use the Python reader (manual; this is NOT chained
               from restore.bat any more -- see "MANUAL PYTHON
               RESTORE" below for details).  Install Python from
               python.org, then run:
                   python D:\standalone_restorer.py ^
                       --repo D:\metadata\<name> ^
                       --password-file C:\path\to\pw.txt ^
                       --target C:\Users\me\restored ^
                       --mount-point E:\
               See "MANUAL PYTHON RESTORE" below for what <name>,
               the password file and --mount-point mean.

CASE D.  The restore completes but some files appear truncated.
         File a bug report with the SHA-256 of the affected file
         and the disc serial number.  This should not happen --
         every blob is authenticated and checked against its
         SHA-256 hash before being written.  A truncation almost
         certainly means a bug in the tool.

────────────────────────────────────────────────────────────────────
PRIVACY / SECURITY
────────────────────────────────────────────────────────────────────

  * The password is written to a file in %TEMP% while the restore
    runs, and so are the share cards you type; a password from
    LCSAS_PWFILE is copied there too.  The script deletes them when
    the restore ends.  If the window is closed first, they stay
    until restore.bat runs again, which deletes every lcsas-pw-*.txt
    file and lcsas-shares-* folder in %TEMP% before it asks for a
    password; you may delete them yourself instead.  If your machine
    has full-disk encryption, this is safe enough.  On a shared
    machine, restore on a computer only you use, or delete those
    files as soon as the restore stops.  Keep the file LCSAS_PWFILE
    names on removable media, and take it away afterwards.

  * The tools folder (%LOCALAPPDATA%\LCSAS-restore) and "Resume
    LCSAS restore.bat" never hold the password.  resume.cfg in that
    folder names only the backup set, the restore folder and the
    drive letters.  The tools folder does hold a copy of the packs
    read so far; they are encrypted, as on the discs.

  * The .exe is fully offline.  It makes no network connections.
    You can run it on an air-gapped machine.

  * Microsoft Defender will scan the binary on first run; this is
    normal and adds a few seconds.

────────────────────────────────────────────────────────────────────
TROUBLESHOOTING -- error messages
────────────────────────────────────────────────────────────────────

"That password is wrong: it does not open the backup set ..."
   -> The script tried the password before the restore, and the
      backup set's key rejected it.  Type it again: check the case
      of each letter and the keyboard layout.  A password with
      characters CMD may change (letters outside A-Z, quotes) is
      safer through the PowerShell lines in "THE PASSWORD" above.
      Q stops the script (exit code 77) and prints "could not
      decrypt the repository with that password".  Nothing was
      restored, and no other recovery tier was tried -- they all
      read the same keys, so they would fail the same way.

"Share card N was not typed right"
   -> The line above it names the word that is not a share word, or
      says that a word is missing or the card's check failed.  Type
      the card again, word by word against the paper.

"Those share cards do not fit together"
   -> Each card is fine on its own, but together they do not rebuild
      the password: they come from different splits (compare the
      Split ID on the cards), or one card was typed twice.

"pack not found: <hex>"  or  "tree blob not found: <hex>"
   -> The pack is on a data disc that is not in a drive, and
      lcsas-restore.exe could not ask you for it.  It asks only
      when it runs in a console window.  Double-click restore.bat,
      or run it from a Command Prompt window, and it shows a box
      that names the disc it needs (see QUICK START above).  A
      script that types the answers itself can set
      LCSAS_INTERACTIVE=on.

"The restore stopped before it finished (code N)."
   -> Code 75: you typed Q at a disc box.  Any other code:
      lcsas-restore.exe stopped on an error shown above.  The files
      restored so far are kept, and so is the tools folder.  To
      carry on, double-click "Resume LCSAS restore.bat" on your
      Desktop, or run the command the message shows: no meta disc
      needed (see "STOPPING AND CARRYING ON" above).  It skips the
      files already there.

"ERROR: the tools folder ... is a folder that already holds other
 files, or a whole drive."
   -> The tools folder (LCSAS_TOOLS_DIR, or the usual
      %LOCALAPPDATA%\LCSAS-restore) holds files the script did not
      put there, or is a whole drive such as E:\.  The tools folder
      is deleted once the restore has finished, so the script will
      not use such a folder, and changed nothing in it.  Set
      LCSAS_TOOLS_DIR to a new or empty folder, or remove the
      setting to use the usual one.

"ERROR: bad zstd blob size"
   -> Data corruption on the disc.  Try another disc with the same
      label.  LCSAS archives normally have two or more discs with
      each label; one should be readable.

────────────────────────────────────────────────────────────────────
COMMAND-LINE REFERENCE
────────────────────────────────────────────────────────────────────

If you are comfortable with CMD/PowerShell: restore.bat is just a
wrapper around lcsas-restore.exe.  The .exe accepts:

    --repo DIR             path to the restic repository
    --password-file FILE   path to a file containing the password
    --target DIR           where to write restored files
    --snapshot ID|latest   which snapshot (default: latest)
    --list-snapshots       print all snapshots; do not restore
    --pack-search DIR      extra dir to scan for pack files
                           (repeatable; one per inserted data disc)
    --verbose              print progress messages
    --catalog FILE         optional path to LCSAS catalog.db

The repository metadata lives under metadata\<name>\ on the disc,
where <name> is the repository's folder (the directory containing
keys\ and index\); run `dir D:\metadata` to list them.

Example:

    cd D:
    recovery\bin\x86_64-pc-windows-gnu\lcsas-restore.exe ^
        --repo D:\metadata\<name> ^
        --password-file C:\path\pw.txt ^
        --target C:\Users\me\restored ^
        --pack-search E:\ ^
        --verbose

────────────────────────────────────────────────────────────────────
ON OLDER WINDOWS (XP / Vista / unpatched 7-8)
────────────────────────────────────────────────────────────────────

If lcsas-restore.exe fails to launch with an error mentioning a
missing api-ms-win-crt-*.dll, your Windows lacks UCRT.  Options
in order of effort:

  A. Install Windows Update KB2999226 (Sep 2015) on Windows 7/8/8.1.
     This adds UCRT.  Most patched systems already have it; if
     yours doesn't, run Windows Update and let it apply pending
     updates.

  B. Move the discs to a Windows 10 or 11 machine.  No installation
     of LCSAS is needed; just plug in the BD reader and double-click
     restore.bat on the newer machine.

  C. Use a Linux/macOS machine instead.  Boot a Linux live USB
     (Ubuntu, Mint, Debian -- any modern distro will do), insert
     the meta disc, and run:
        sh /media/<user>/<DISC>/restore.sh ~/restored
     The Linux binary has NO UCRT dependency; it only needs glibc
     or musl, both universal on Linux.

  D. Use the Python reader.  Install Python 3 from
     python.org (Python 3.10 or newer; the script exits with a clear
     message on anything older), then run:
        python D:\standalone_restorer.py ^
            --repo D:\metadata\<name> ^
            --password-file C:\path\to\pw.txt ^
            --target C:\Users\me\restored ^
            --mount-point E:\
     This works on any Windows that runs Python 3.10 or newer,
     which rules out Windows 7 and older.  Note that
     restore.bat does NOT chain to this script for you any more --
     you invoke it directly.  See "MANUAL PYTHON RESTORE" below.

  E. A separate .exe for older Windows is not planned.  On
     Windows XP, Vista or an unpatched Windows 7, use option A, B
     or C.  Option D does not help there: Python 3.10 does not
     install on Windows 7 or older.

────────────────────────────────────────────────────────────────────
MANUAL PYTHON RESTORE (last resort, no binaries needed)
────────────────────────────────────────────────────────────────────

If both lcsas-restore.exe and rustic-static.exe are unusable on
your host -- missing UCRT, antivirus quarantine, broken bits, wrong
architecture -- you can still restore using the Python reader
(standalone_restorer.py) that ships on every meta disc.

restore.bat does NOT chain to this script.  Older versions did, but
the chain required the `py` launcher to be on PATH, which is not a
safe assumption on a stock Windows host that has never had Python
installed.  We removed the chain so the .bat fails fast with a
clear error instead of pretending a Python restore is automatic.
The standalone_restorer.py file is still on the meta disc; you
invoke it directly when you need it.

STEP 1.  Install Python 3 from https://www.python.org if it is not
         already on the host.  Python 3.10 or newer is required (the
         script exits with a clear message on anything older).
         Tick "Add Python to PATH" in the installer.

STEP 2.  Open a Command Prompt at the meta disc root.  For example,
         if the disc is mounted at D::

             D:
             cd D:\

STEP 3.  Put the password in a file.  The script reads the password
         from a file (--password-file); it never asks for it
         interactively.  Open Notepad, type the password and nothing
         else, and save it as e.g. C:\Users\me\pw.txt.  The password
         is readable on screen and on disk while the file exists --
         on a shared machine, save it to removable media instead and
         delete it as soon as the restore finishes.

STEP 4.  Run the Python reader.  --repo, --password-file and
         --target are all required flags; there are no positional
         arguments.

             python standalone_restorer.py ^
                 --repo D:\metadata\<name> ^
                 --password-file C:\Users\me\pw.txt ^
                 --target C:\Users\me\restored ^
                 --mount-point E:\

         <name> is the repository's folder under D:\metadata\ -- the
         directory that contains keys\ and index\.  Run
         `dir D:\metadata` to list the repositories.

         Pack data lives on the data discs, not under metadata\.
         Add one --mount-point <letter>:\ argument per inserted
         data disc; with a single drive, when a pack is missing the
         script pauses so you can swap discs, then re-scans the
         mount points.  Run with --help for the full flag surface.

STEP 5.  Wait for "Restore complete".  Files are byte-equal to the
         original snapshot.  Symlink, ACL, owner/group and other
         POSIX-specific metadata are dropped on Windows (same caveats
         as the binary path).

The Python reader has NO external dependencies beyond the
Python standard library; it implements AES-256 and the restic blob
format directly.  It is slower than the C binary -- typically by a
factor of 5-20x -- but works on any Windows that runs Python 3.

────────────────────────────────────────────────────────────────────
PHYSICAL DISC PROBLEMS
────────────────────────────────────────────────────────────────────

If the disc itself is unreadable (cracks, scratches, drive errors):

  1. Try a different optical drive (drives differ in how aggressively
     they retry weak sectors).
  2. The discs include RS03 error-correction data (~15% of capacity),
     and the meta disc ships its OWN repair tool -- lcsas-ecc.exe --
     so you do NOT need to install dvdisaster or any other program.

     a. Make an image of the scratched disc.  Use any imaging tool;
        the free, open-source ImgBurn (Read mode: Disc -> Image) is a
        common choice on Windows.  Save it as, e.g., C:\temp\disc.iso.

     b. From a CMD prompt at the meta disc root, run the bundled
        helper, which scans the image and offers to repair it in
        place:

           restore.bat --check-disc C:\temp\disc.iso

        (Or call the tool directly:
           recovery\bin\<arch>\lcsas-ecc.exe verify C:\temp\disc.iso
           recovery\bin\<arch>\lcsas-ecc.exe fix    C:\temp\disc.iso
         -- <arch> is your machine's dir under recovery\bin\, normally
         x86_64-pc-windows-gnu.)

     If damage exceeds the parity, lcsas-ecc reports it and refuses a
     partial repair rather than returning a silently-broken image.

  3. Then mount the repaired .iso via Windows' built-in mount
     (right-click -> Mount) and re-run restore.bat against the
     mounted drive.
  4. If you have more than one disc with the same label, any one
     readable disc is enough.  The binaries and packs on them are
     bit-identical.

The in-house repair tool (lcsas-ecc) is built from source we ship and
audit on the meta disc; the dvdisaster RS03 reference source is pinned
in recovery/UPSTREAM.sha256 and travels on the disc too.  There is no
dependency on any external download or fan-maintained mirror.
